# Audit: May 2026 — 7 Fixes Applied

Full audit of 54+ files across engine, themes, components, providers, stores, routes. Found 8 issues — 4 bugs, 3 inconsistencies, 1 perf. All fixed and verified with `npm run build` (zero errors).

## Fixes Applied

### Fix #1+#4: TransitionManager onDispose callback (orphan groups + abort cleanup)
**Files**: `src/engine/transition.ts`, `src/engine/engine.ts`
**Problem**: TransitionManager called `handle.dispose()` directly but never removed objects from `mainScene`. During rapid theme switches (abort), the stale `next` handle was just overwritten — no dispose at all.
**Solution**: TransitionManager now receives `onDispose: (SceneHandle) => void` callback. Engine passes its `disposeScene` helper (which handles both `mainScene.remove(obj)` + `handle.dispose()`). Abort path in `transition()` also calls `onDispose(state.next)`.
- `disposeScene` must be declared BEFORE `createTransitionManager` to avoid use-before-declaration
- All `dispose()` calls replaced with `onDispose()` in transition.ts

### Fix #7: Duplicate easeInOutCubic
**Files**: `src/engine/transition.ts`, `src/engine/math.ts`
**Problem**: `easeInOutCubic` defined in both files.
**Solution**: Removed from transition.ts, imported from `./math` instead.

### Fix #2: Same-theme re-click guard
**File**: `src/engine/engine.ts`
**Problem**: Guard only blocked transitions when actively transitioning — clicking same theme during idle rebuilt the entire scene.
**Solution**: `if (currentModule?.sceneKind === m.sceneKind) return;` — single line at top of `setTheme()`, blocks in all states.

### Fix #3: Blockchain setOpacity multiplicative → absolute
**File**: `src/themes/blockchain/scene.ts`
**Problem**: `material.opacity = material.opacity * t` caused multiplicative drift on subsequent calls.
**Solution**: First call snapshots base opacity to `material.userData._baseOpacity`. Subsequent calls do `_baseOpacity * t`. Works for MeshBasicMaterial, LineBasicMaterial, ParticlesMaterial.

### Fix #8: getDensity indexOf → forEach index (O(n²) → O(n))
**File**: `src/themes/software/scene.ts`
**Problem**: `plane.sprites[plane.drops.indexOf(d)]` — O(n²) inside per-frame density calc.
**Solution**: Changed `plane.drops.forEach((d) => ...)` to `plane.drops.forEach((d, i) => ... plane.sprites[i])`.

### Fix #5: Document --color-accent-red as intentional
**File**: `src/app.css`
**Solution**: Added comment: `/* universal — not theme-specific, used for semantic elements (heart, status dots) */`

### Fix #6: SSR flash blocking script
**File**: `src/app.tsx`
**Problem**: Theme set via JS after hydration — potential flash of wrong theme colors.
**Solution**: Blocking inline `<script>` in `<head>` that reads `localStorage.getItem('portfolio-theme')` and sets `document.documentElement.setAttribute('data-theme', t)` synchronously before first paint.

## Part 2: Build & Runtime Fixes (May 2026 continuation)

### Fix #9: tsconfig.json — TypeScript 6.0.3 build breakage
**File**: `tsconfig.json`
**Problem**: `baseUrl` deprecated in TS 6.0; `"vinxi/client"` refers to non-existent file (SolidStart issue #1454); test globals missing.
**Solution**: Remove `baseUrl` (use `paths` only), change `"vinxi/client"` → `"vinxi/types/client"`, add `"vitest/globals"` to `types`.

### Fix #10: Global keydown guard for editable elements
**File**: `src/engine/engine.ts`
**Problem**: Theme-switching key handler intercepted keystrokes in form fields, text inputs, and contentEditable elements.
**Solution**: Handler now checks `event.target` and skips INPUT (except checkbox/radio/button/etc), TEXTAREA, SELECT, and contentEditable.

### Fix #11: AI scene entrance animation — double-counting + per-material opacity
**File**: `src/themes/ai/scene.ts`
**Problem**: `entranceTimer += _delta * 1000` incremented timer twice (once in scene, once in transition manager). Group `scale.setScalar()` approach had z-fighting issues.
**Solution**: Removed `entranceTimer` manual increment (transition manager calls `entrance(elapsed)` directly). Switched from group scale to per-material opacity traversal for entrance effect.

### Fix #12: GLSL 3.0 ES `#version 300 es` duplication bug
**File**: `src/engine/engine.ts` (SCANLINE_SHADER)
**Problem**: Shader included `#version 300 es` explicitly. Three.js 0.184 hardcodes this directive as the first line of every ShaderMaterial. Result: `#version directive must occur before anything else` — complete render failure.
**Solution**: Removed `#version 300 es` from both vertex and fragment shader sources. Three.js injects it correctly. Set `material.glslVersion = THREE.GLSL3` (already present) to prevent `gl_FragColor` define injection. Declared `out vec4 fragColor;` explicitly. Macros `#define varying in/out`, `#define texture2D texture` are benign for existing GLSL 3.0 ES syntax.

### Fix #13: quality.ts — null pointer on Firefox/Safari
**File**: `src/engine/quality.ts`
**Problem**: `getParameter(...)?.toLowerCase()` — optional chaining on the return value, not the method. `getParameter` returns `null` in Firefox/Safari (WEBGL_debug_renderer_info unavailable/unreliable).
**Solution**: `(getParameter(...) ?? "").toLowerCase()` — nullish coalescing before string method call.

### Fix #14: FXAA disabled on low GPU tier
**File**: `src/engine/engine.ts`
**Problem**: EffectComposer and FXAA pass were created even on low GPU tier, consuming resources.
**Solution**: `useComposer = quality.tier !== "low"` — on `low` tier, rendering goes directly to default framebuffer. `fxaaPass` declared as `let fxaaPass: ShaderPass | null`.

### Fix #15: i18n `t()` extended with optional defaultValue
**File**: `src/stores/i18nStore.tsx`, 11 component files
**Problem**: Components used `messages()?.prop || "Fallback"` pattern — verbose, duplicate fallback logic across files.
**Solution**: `t(key: string, defaultValue?: string): string` now accepts optional `defaultValue`. Components migrated to `t("prop", "Fallback")`. Fallback only used when messages aren't loaded or key is missing.

## Part 3: Audit Follow-up (May 2026 cont.)

### Fix #16: Lucide Solid deep imports
**Files**: `Hero.tsx`, `Navbar.tsx`, `Contact.tsx`, `About.tsx`, `Footer.tsx`, `ProjectModal.tsx`
**Problem**: 6 components used barrel imports `from "lucide-solid"` — ~400KB bundled vs ~2KB per icon.
**Solution**: Replaced all with deep imports (`lucide-solid/icons/component-name`).

### Fix #17: WebGL context loss/restored handling
**File**: `src/engine/engine.ts`
**Problem**: No handling for `webglcontextlost`/`webglcontextrestored` events — engine continued running and threw on lost context.
**Solution**: Added `contextLost` boolean flag, event listeners on `renderer.domElement`. Render loop skips all WebGL calls when context is lost. Listeners cleaned up in `dispose()`.

### Fix #18: Theme import failure recovery
**File**: `src/themes/registry.ts`
**Problem**: `loadTheme()` had no `.catch()` — failed dynamic imports propagated as unhandled rejections.
**Solution**: `loadTheme()` now returns `Promise<ThemeModule | null>`. Catches import errors, clears cache, logs, returns `null`. Also uses Promise cache (not resolved value) to prevent race conditions.

### Fix #19: Theme index.ts factory (DRY)
**Files**: `src/themes/create-theme-module.ts` (new), all 4 `themes/*/index.ts`
**Problem**: 4 theme index.ts files had identical structure (~36 lines each) with manual `Object.freeze`.
**Solution**: Created `createThemeModule(config: ThemeConfig): ThemeModule` factory. Each theme's index.ts now ~33 lines of pure data (colorScheme, cameraPreset, postPreset, createScene reference). Factory handles freeze.

### Fix #20: Removed empty directories
**Files**: `src/styles/` (deleted), `=0.5.0` (deleted), stray files removed in previous session.

### Fix #21: ESLint `solid/reactivity` warning fixed
**File**: `src/stores/i18nStore.tsx`
**Problem**: Signal `language()` read inside async `.then()` callback — invisible to SolidJS reactivity tracker, causing ESLint warning.
**Solution**: Extract `const lang = language()` before the fetch chain — synchronous read makes signal tracked.

### Fix #22: @vitest/coverage-v8 installed
**File**: `package.json`
**Solution**: `npm install -D @vitest/coverage-v8`. Added `test:coverage` script: `vitest --run --coverage`.

### Fix #23: JSDoc for lerpColor limitation
**File**: `src/engine/math.ts`
**Solution**: Added `@note Only supports 6-character hex strings (#RRGGBB)` to `lerpColor` JSDoc.

## Part 4: Code Quality & Architecture Fixes (May 2026)

### Fix #24: ThemeId string union → SceneKind enum
**Files**: `themeStore.ts`, `registry.ts`, `Hero.tsx`, `themeStore.test.ts`
**Problem**: `type ThemeId = "ai" | ..." defined in themeStore.ts while `enum SceneKind` existed in `types.ts` with same 4 values — duplicate source of truth.
**Solution**: Removed `ThemeId` type. All consumers now use `SceneKind` enum from `types.ts`. THEMES array uses enum values. REGISTRY keys are enum strings (matching CSS `data-theme` selectors).

### Fix #25: Shared canvas texture utility
**Files**: `src/engine/canvasTexture.ts` (new), `blockchain/scene.ts`, `software/scene.ts`, `web/scene.ts`
**Problem**: ~60 lines of canvas creation + `getContext("2d")` + `new CanvasTexture(...)` duplicated across 3 themes.
**Solution**: Extracted `createCanvasTexture(options, draw)` factory with callback-driven API. Uses separate `MinificationTextureFilter`/`MagnificationTextureFilter` types with `as` casts for Three.js filter type mismatch.

### Fix #26: AI scene opacity guard + frame-based modulation
**File**: `src/themes/ai/scene.ts`
**Problem**: Forward pass ran every ~0.6s even when scene invisible during transitions. Attention shimmer used `Math.floor(time * 60) % 4` (time-based, not frame-based — drifts on high-refresh).
**Solution**: `frameCount` counter incremented per-update. Shimmer uses `frameCount % 4`. Forward pass guarded by `if (entranceOpacity >= 1.0)`.

### Fix #27: AI scene respects config.colorScheme
**File**: `src/themes/ai/scene.ts`
**Problem**: AI scene marked `_config` unused, hardcoded 16 hex colors. Only scene ignoring the contract.
**Solution**: Changed to `config: SceneConfig`. Moved LAYERS from module-scope into factory closure using `cs.primary/secondary/tertiary`. Manifold clusters now use `THREE.Color[]` array from parsed scheme. Only `#F5C842` (attention yellow) remains as internal constant.

### Fix #28: WebGL context restore rebuilds scene
**Files**: `engine.ts`, `transition.ts`
**Problem**: Context restore just reset `contextLost` flag — rendered blank after GPU loss since all WebGL objects invalidated.
**Solution**: `onContextRestored` disposes old scene, rebuilds from `currentModule`, calls `transitionManager.forceScene()`. New `forceScene` method aborts pending transition, disposes current, installs new scene at full opacity.

### Fix #29: CSS @theme duplication documented
**File**: `src/app.css`
**Solution**: Added comment documenting that `@theme` block values intentionally mirror `ai/theme.css` for Tailwind v4 token registration.

### Fix #30: JSON-LD typed interface
**File**: `src/entry-server.tsx`
**Solution**: Added `StructuredData` interface, extracted typed constant, replaced inline JS object.

### Fix #31: i18nStore tests + transition forceScene tests
**Files**: `src/stores/i18nStore.test.tsx` (new, 19 tests), `src/engine/transition.test.ts` (+3 forceScene tests)
**Problem**: i18nStore had zero test coverage. transition.ts forceScene was untested.
**Solution**: i18nStore tests cover module-level signal defaults, `t()` nested key resolution, setLanguage signal+localStorage, fetchError. Transition tests cover forceScene replacement, abort+during-transition, and empty-state scenarios. Total: 143 tests (was 121).

## Part 5: Accessibility, Performance, SEO, Error Handling, Tests (May 2026)

### Fix #32: Duplicate IntersectionObserver → shared hook
**Files**: `src/hooks/createVisibilityObserver.ts` (new), About, Contact, Projects, Experience, Skills, Stats (6 files updated)
**Problem**: IntersectionObserver pattern duplicated in 6 section components (~60 lines).
**Solution**: Created reusable `createVisibilityObserver(opts)` hook with `threshold` (default 0.15), returns `isVisible` signal. Uses `onMount`/`onCleanup` for SolidJS lifecycle.

### Fix #33: Duplicate social icon map → shared module
**Files**: `src/hooks/socialIcons.ts` (new), Hero.tsx, Contact.tsx
**Problem**: SOCIAL_ICON_MAP and platform matching logic duplicated in Hero and Contact.
**Solution**: Shared module exports `SOCIAL_ICON_MAP: Record<string, typeof icon>` and `resolveSocialIcon(imgAlt: string)`.

### Fix #34: Keyboard accessibility for project cards
**File**: `src/components/Projects.tsx`
**Problem**: Project cards were `<div>` without keyboard interaction — inaccessible to keyboard users.
**Solution**: Added `role="button"`, `tabIndex={0}`, `onKeyDown` (Enter/Space), `aria-label`.

**Files**: About, Experience, Skills, Projects, TypewriterText, RotatingTypewriter, NotFoundPage, ProjectModal

**Solution**: Added `aria-hidden="true"` to all decorative lucide icons. Skill bars now have `role="progressbar"`, `aria-valuenow/valuemin/valuemax/aria-label`.

### Fix #36: WCAG AA text-muted contrast

### Fix #37: ErrorBoundary on all sections
**Files**: `src/routes/index.tsx`, doom.tsx, NotFoundPage.tsx
**Problem**: No error isolation — single component error broke entire page.
**Solution**: Wrapped all 7 section components in `<ErrorBoundary fallback={() => null}>`. Graceful degradation.

### Fix #38: I18n error banner (fetchError was set but never shown)
**Files**: `src/components/I18nErrorBanner.tsx` (new), routes/index.tsx, doom.tsx, NotFoundPage.tsx

**Solution**: Dismissible alert banner reading `fetchError` from I18nContext. Shows error message with dismiss button. Uses direct signal access pattern (render-prop `<Show>` didn't render text in SolidJS 1.9.12).

### Fix #39: SEO improvements

**File**: `src/routes/doom.tsx`
**Problem**: JS-DOS (~4MB) loaded even on invalid routes or if user didn't play.
